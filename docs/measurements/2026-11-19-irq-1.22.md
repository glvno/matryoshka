# The audio interrupt, 1.21.0 against 1.22.0, 2026-11-19

The 1.22.0 qualification (`release/qualification/v1.22.0.json`, `hardware.cpu_survey.against_1.21.0`) read the audio interrupt with 8 keys held 3 to 5 % longer than on 1.21.0, on patches whose bytes did not change: Cassia 1 1869.7 → 1964.8 µs, Algo Four 1785.9 → 1836.9 µs, the owner's edited Hera 6 2015.6 → 2096.0 µs. With every master FX stage on, the worst steady load read up to 3.8 points higher. Issue #1139 asked for the cause. This record finds no regression in the firmware: the two qualification readings were taken in different sessions, and the 1.22.0 one during traffic on the USB link.

## Method

- **Builds:** the release packages, 1.21.0 (release run 44608208590) and 1.22.0 (release run 44645737007), each installed on the test rig through `npm run device:scenarios -- --install RUN --only checkDualCore` (the boot check first, [D-123](../ledger/releases.md#D-123)). Order in one session: 1.22.0 as the previous agent left it (install a), 1.21.0, 1.22.0 again (install b).
- **Block times:** `tools/m1_link.py --rig blocktime 4 --notes 8`, three windows per patch and install. Factory slots by program change: Cassia 1 (program 18), Algo Four (6), the owner's edited Hera 6 (3), the same slots and bytes as in the qualification. Then 1.21.0's qualification patches with every FX stage on (`build/release-1.21.0/qual/rig1210/bankfx`), uploaded live: the same bytes on both builds.
- **Load:** `tools/rig_cpu_survey.py` over the same 21 FX patches, transport stopped, worst steady load as in the qualification.
- **Emulator:** the timing model (`M1EMU_TIMING`, `M1EMU_PROF`, `m1emu cpu --modtime`, 8 keys) on 1.21.0, 1.22.0 and each firmware CI build between them.
- **Raw data:** [irq-2026-11-19-rig-1.21-1.22.json](irq-2026-11-19-rig-1.21-1.22.json).

## The audio interrupt on the rig

Means over a 4-second window, µs, in windows where TIMER5's body averaged its usual 3.0 to 3.4 µs (see below):

| Patch | 1.21.0 | 1.22.0, install a | 1.22.0, install b |
|---|---|---|---|
| Cassia 1 (program 18) | 1925 | 1897 (−28) | 1946 (+21) |
| Algo Four (program 6) | 1843 | 1768 (−75) | 1818 (−25) |
| Hera 6, edited (program 3) | 2048 | 2034 (−15) | 2059 (+11) |
| Cassia 1 fx | 2117 | 2105 (−12) | 2131 (+14) |
| Expander S fx | 2338 | 2321 (−16) | 2340 (+3) |
| Hera 6 fx | 2047 | 2038 (−9) | 2059 (+12) |
| Algo Four fx | 2177 | 2160 (−17) | 2189 (+12) |

- Within one install, the three windows agree to 1 to 3 µs. Between two installs of the same 1.22.0 package, the same patch differs by 9 to 50 µs. 1.22.0 against 1.21.0 lies inside that spread: −75 to +21 µs, about −10 µs on average.
- The same 1.21.0 package read Cassia 1 at 1869.7 µs in the qualification's session and 1925 µs here: 55 µs between sessions, on the same bytes.
- Core 1, which takes no TIMER5 interrupt, shows the same: Cassia 1 1730 µs (1.21.0) against 1714 and 1743 µs (1.22.0).

## What raised the qualification's reading: traffic on the USB link

In some windows TIMER5's C body averaged 4.5 to 5.0 µs a tick instead of 3.0 to 3.4 µs. TIMER5 runs the key scan every tick and the USB and MIDI polls every fifth (`fm1_timer5_irq`), and the polls take longer while the host sends: `tools/m1_link.py --rig t5` read 2.7 to 3.8 µs a poll on a quiet link and 11 to 13 µs while `tools/rig_cpu_survey.py` uploaded patches. In such a window the audio interrupt is 60 to 75 µs longer: TIMER5 nested in it 35 to 45 µs more, and the voices about 30 µs more on both cores (TIMER5's flash code takes cache lines from them). On 1.22.0, install a:

| Patch | Quiet link | USB traffic |
|---|---|---|
| Algo Four (program 6) | 1768 (TIMER5 3.04 µs) | 1841 (4.50 µs) |
| Hera 6, edited (program 3) | 2034 (3.21 µs) | 2099 (4.77 µs) |

The qualification's 1.22.0 readings, Algo Four 1836.9 µs and Hera 6 2096.0 µs, match the traffic column. They were taken a minute after the install, when the link was busy (on 1.21.0 here, the first `t5` after the install read 3.83 µs a poll against 3.10 later). The 1.21.0 readings they were compared with came from another session.

The load survey shows the same. 1.22.0 against 1.21.0 in one session, every FX stage on, transport stopped: −1.8 to +2.9 points, mean −0.04 (Meridian 8 +2.9, 808 Kit +1.7, Verona Drum 1 −1.8). A second 1.22.0 survey run while `t5` reads went to the rig alongside it read +1.1 points on average, with Algo Four +3.8 and Hera 6 fx +3.2: the qualification's largest rises (Algo Four 75.5 → 79.3). Two 1.21.0 surveys of the same patches in different sessions differ by −1.3 to +2.3 points.

## In the emulator

The timing model reads 1.21.0 → 1.22.0 at 8 keys as Cassia 1 1921.7 → 1943.5 µs, Algo Four 1915.9 → 1895.1 µs; with every FX stage on, Cassia 1 +19, Expander S −11, Hera 6 +18, Algo Four −20 µs. Commit by commit (#1122, #1126, #1130, #1131, the freeze) the steps go both ways, within ±2 %. Between the releases the engine's hot code moved in the flash (`process` +7,392 B, mostly `eq_design` placed before it; `render_item` and `eng_render` about +8,000 B), and `process` itself grew 602 B. A build of 1.22.0 with the 81 functions the profiles run pinned at their 1.21.0 addresses (CI run 44656186309, branch `irq-exp-pin121`, not merged) read 20 to 58 µs shorter than 1.22.0 in the emulator. On the rig, installed after 1.22.0's install b, it read Cassia 1 1936, Algo Four 1817, Hera 6 2051, and the FX patches 2122, 2337, 2053 and 2162 µs: inside the spread of the two 1.22.0 installs. The layout change is not worth its machinery.

## Conclusions

- 1.22.0 does not lengthen the audio interrupt against 1.21.0: the difference is inside the rig's spread between two installs of one package.
- A rig comparison of two builds needs both in one session, installed alternately, and windows with a quiet USB link. TIMER5's body time, which `blocktime` prints, tells a busy link from a quiet one.

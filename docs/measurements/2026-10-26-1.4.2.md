## Timing on the device

CoreMIDI schedules note events and panel test commands in advance with host timestamps. A temporary live patch
connects Main's pitch to an Oscillator and Main's gate to a VCA. A low-pass Filter at 12 kHz sits before the VCA.
The Output level is 0.4. The rig's USB audio is captured through PortAudio at 44.1 kHz stereo. Each capture has
its full sample count and no host overflow. Notes are counted from one-millisecond waveform peak windows.

The first three runs send 50 notes, 80 ms apart, held for 30 ms. SELECT or ALGO turns arrive 10 ms after every
second note begins. The fast runs send 200 notes, 20 ms apart, held for 6.67 ms. Alternating octave-button presses
arrive 1 ms after every second note begins and release 34 ms later. The test commands exercise the firmware's
panel input path. No saved patch is changed by these probes.

| Test | Sent | Heard | Note interval range |
|---|---:|---:|---|
| idle | 50 | 50 | 77.8–81.8 ms |
| select | 50 | 50 | 77.8–81.8 ms |
| algo | 50 | 50 | 77.8–81.8 ms |
| idle-fast | 200 | 200 | 17.0–22.9 ms |
| octave-fast | 200 | 200 | 17.0–22.9 ms |

The screen-changing runs match their idle controls. This checks sounding notes and spacing, not absolute
input-to-audio latency. The engine's roughly 2.9 ms blocks also cause a small interval spread when idle.

Device timing measurements use USB MIDI. The regression also exercises the actual TRS parser, including clock
bytes between note bytes, through the shared queue and dispatcher. Precise physical TRS timing is not measured.
The original main-branch reproduction and before/after results are recorded in
[PR #371](https://github.com/glvno/matryoshka/pull/371).

## Other checks

- The exact release binary passed 158 emulator smoke checks, with no failed checks or level warnings.
- The matching MIDI-enabled emulator build from commit `bde3aa0` passed all 26 editor/MIDI scenarios.
- The installed release package passed all 26 scenarios on the registered device, using the release editor.
- The firmware's Cassia 1 patch sounded with three held notes. Its audio processing peaked at 2,413 microseconds
  of a 2,902-microsecond budget, with no overload. The normalized output peak was 5,585.
- Golden audio comparisons, USB tests, panel and MIDI regressions, web tests, type checks and generated-header
  checks passed. The release build had no compiler warnings. Its image is 335,972 bytes, static RAM is
  17,008 of 24,576 bytes, and its pool is 381,032 of 417,792 bytes.

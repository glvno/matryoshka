# The 1.20 headroom build on the test rig, 2026-11-18

The 1.20 headroom branch (`headroom-1.20`) gathers the CPU work for release 1.20 (#868, #979, #1073): the float Multimode filter, Ladder and Formant filter (#1074), the float Reverb, Delay filters and Low pass gate with control-rate float (#1076), hot code in RAM (#1078), and the two-core plan from the rig's module costs (#1079), on main `27c04c32`. This record holds the one full-bank comparison with main and the surveys the CPU estimate is refitted to.

## Builds and method

- **1.20:** firmware CI run 44262067788 (the branch with the plan costs below). **Main:** firmware CI run 44250901930 (`27c04c32`). Both were installed through the boot check (`emu:boot`, [D-123](../ledger/releases.md#D-123)). On the 1.20 build `emu:smoke` passed too (301 checks, 0 failed).
- **Load** (`tools/rig_cpu_survey.py`): each patch at 0, 1, 4 and 8 held keys, 2 seconds each, transport stopped and running. The steady value is the lower median of a phase's samples after the first. A cell is the largest steady value over the key counts, as a share of the 2,902 µs half-block. Main and 1.20 were surveyed back to back in the same session.
- **Block times** (`tools/m1_link.py --rig blocktime 3 --notes 8`): means at 8 held keys.
- **Memory** (CI build log, against main): `.lowram` 48 B free (same), pool headroom 8,200 B (same), RAM 4,476 B free (same), image 555,996 B (main 558,772 B). NOINIT holds the RAM code (12,604 B) with 156 B left.

## The refit ([D-365](../ledger/engine.md#D-365))

The estimate is held to the 1.14 bank (`web/src/cpu-survey-factory-1.14.json`), so that bank was surveyed again on the 1.20 build, with the poly patches at more voices than they play: [stopped](cpu-survey-2026-11-18-rig-headroom120-bank114.json), [running](cpu-survey-2026-11-18-rig-headroom120-bank114-run.json); voices [stopped](cpu-survey-2026-11-18-rig-headroom120-voices114.json), [running](cpu-survey-2026-11-18-rig-headroom120-voices114-run.json). No phase shed a voice. `web/scripts/cpu-rig-fit.ts` fitted each engine's factor to them (`web/scripts/cpu-costs.ts` `RIG`); the scale stays frozen. Each 1.14 patch's estimate reads from exactly the rig to 3.9 points over it, at every voice count measured (the most: Expander S at 6 voices, 70.0 % against 66.1 %).

## The RAM function list and the unrolled loops (emulator)

The RAM list (`tools/build.py` `FAST_TEXT`) came from a profile of a fixed-point build. The float kernels changed the hot code, so it was chosen again from the emulator's profile (`m1emu cpu --modtime`, `M1EMU_PROF`, `M1EMU_TIMING`) of the combined build with the RAM code off, over the poly benchmark: 41 functions, 12,640 bytes, the most instruction-cache refills per byte. Worst steady load in the emulator's timing model, %:

| Patch | Flash, not unrolled | Flash, unrolled | RAM code, unrolled |
|---|---|---|---|
| Hera 6 gauze 2 | 82.3 | 78.8 | 70.2 |
| Hera 6 fx4 | 84.7 | 82.6 | 73.6 |
| Oracle V fx | 90.7 | 90.0 | 80.4 |
| Oracle V fx4 | 91.8 | 90.7 | 82.3 |
| Cassia 1 fx4 | 92.2 | 87.1 | 81.7 |

On this build unrolling saves up to 5 points in the model, although it adds instruction-cache refills (about 550 to 640 a half). Two sites cost instead: unrolled, `signal_mean` and `m_bypass` stop being inlined. Their loops are no longer unrolled. With the RAM code the refills fall to 222 to 399 a half.

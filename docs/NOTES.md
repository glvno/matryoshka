## How the flash path works (from reading Felucca)

SysEx over USB MIDI. The device *pulls* blocks: it sends read requests (cmd 0x30) for addresses in a "logical image" (package minus 20 marker bytes after each of the first 20 32-byte blocks); the host answers with `response()`. Step 1: running firmware checks the package (finish addr `0xE0000000`) and stages the loader; step 2: the loader (`usb_hid_ota.bin`, marker `FELUCCA-LOADER-1`) reads everything and writes flash (finish `0xF0000000`), then reboots. Identity handshake `F0 00 32 45 00 00 00 40 7F F7`; upgrade command `F0 22 24 35 7F F7`. Recovery: an interrupted write leaves the device in the loader that was writing: ours / Felucca's identify as `ota-FM-1_800` / `ota-FM-1_9XY` (USB name "Felucca Update", 1209:0002), M-VAVE's as `ota-FM-1_015`; run the same install again. Only a fitting loader is fed (`loaderFits` in fm1ota.js, `loader_fits` in fm1_install.py): M-VAVE's loader rewrites the flash head from the package, so it only ever gets the official V15, Felucca-type loaders everything else (our loader reports `ota-FM-1_800` for release builds too). Return to stock: official V15 file, sha256 `db1642b2…edb8a`, bundled in `web/public/firmware`. OCT− + OCT+ held 5 s, MENU > UPDATE MODE, the boot guard and the `7D` SysEx enter the chip's mask-ROM mode (WL80UBOOT, 4C4A:8057), which nothing in this project can talk to (tracked as an issue).

## Gotchas

- **Chromium aborts the whole browser (SIGILL) in `midi::MidiManager::SetInputPortState`** (its ALSA Web MIDI backend, Chromium 151 on this NixOS box; `coredumpctl list` shows a series) when MIDI ports change while any page holds MIDI access, e.g. the FM-1 re-enumerating after a reset or during a firmware update, or other programs (`fm1_install.py`, `m1_link.py`: rtmidi/ALSA clients) coming and going. The web app therefore requests MIDI only on a click (Enable MIDI keyboard, Connect FM-1, the flasher) and has Release MIDI (reload). Prefer `tools/fm1_install.py` for flashing; close the app's tab before running CLI tools. Headless Chromium runs I started also dump core when killed.

- Never flash untested firmware that lacks Felucca's OTA handling; that removes the way back (apart from the loader/stock path).
- `pkill -f "<pattern>"` inside a Bash tool call matches the shell itself; use `pgrep`+PID or a pidfile.
- Web MIDI + SysEx needs Chrome/Edge and https or localhost.
- Engine buffers are 128 frames; modules read `ctx.n` (≤128), not `BLOCK`.
- Keep patch-format changes in `patch.ts` and update `validatePatch`, presets and tests together.

## Delay sync / ping-pong (host-tested, golden pass; not flashed)

- Module `delay`: inputs `in`, `clk`; outputs `out`, `r`; params `time`, `fb`, `mix`, `sync` (toggle), `pingpong` (toggle). Sync: the same `time` knob picks a note length (range split in `DELAY_DIVS`, shortest first: 1/16T .. 1/1, shared with the LFO's `div`; `ParamDef.altText` shows the name, LCD special case in `ui.c`, `delay_div()` in engine.c). Tempo = the last 24 pulses of `clk` (the Main module's clock, 24 ppqn), smoothed; 120 bpm until a clock has come in. Ping-pong: one buffer split in two halves, so the time is limited to ~525 ms then; `out` = left, `r` = right (without ping-pong `r` = `out`); `fb` and `mix` apply to both sides. Binary patch format 8.

## Main clock output (host-tested, golden pass; not flashed)

## 2026-10-21: USB audio out (branch `usb-audio`; host-tested and emulator-tested only, not run on a device)

The FM-1 now also presents itself as a class-compliant UAC1 recording device: the master output (after MASTER and the
mixer's patch level, the same words the codec gets) as 16-bit stereo at 44.1 kHz, so a computer can record it over the
cable. Felucca's whole path was already in `usb.c` behind `FELUCCA_UAC`; this session switched it on and fitted it.

- **Build:** `modular.c` defines `FELUCCA_UAC 1` under `#ifndef` (it was a hard `0`, so `tools/build.py`'s env flag was
  ignored); `FELUCCA_UAC=0 python3 tools/build.py` builds without. `FELUCCA_UAC_48K 0` and an `#error` if set: 48 kHz needs
  Felucca's `uac_fir.h`, not in this repo. The format descriptor lists 44100 alone; SET_CUR is acknowledged and changes
  nothing, GET_CUR / MIN / MAX answer 44100. RAM: .data+.bss 13104 -> 15440 B of 24576 (the 2 KB ring); image +1.9 KB.
- **Render path (`audio.c`):** `uac_render_start()` as a half starts (samples the ring's fill), `uac_tap(o, 128)` after
  the half's words are written (the render or the silence while `eng_run` is 0). The I2S words carry 24 bit in the low
  bits: `UAC_IN_SHIFT 8` in usb.c's `uac_tap` (Felucca fed it 16-bit values; `uac_s16` clamps, it does not scale).
- **The ring's band moved: 160..208 frames, prime 184** (Felucca: 80..128, prime 104). Felucca tapped block by block
  during its render; `eng_render` makes all 128 frames before the tap, and a heavy patch takes up to 85 % of the half
  (the overload guard's limit), so up to ~3 packets leave the ring before a render's frames arrive. With the old band
  the drift test underran ~20 times a second at a 2.6 ms render. Latency now ~5.7 ms on average.
- **Update mode keeps the MIDI-only device** (`usb_uac_on`, `usb_uac_switch` in usb.c): with it off, `get_desc` returns
  `DEV_DESC_MIDI` / `CFG_DESC_MIDI`, byte for byte what a `FELUCCA_UAC=0` build (= main before this) presents (same
  PID 1209:0001, "Modular-1", bcdDevice 3.00), EP4 is not set up, and SET_INTERFACE 2 / SET_CUR / GET_CUR / CLEAR_FEATURE
  on 0x84 stall. The boot paths decide before the first attach: `fm1_main` now starts TIMER5, waits its 30 ms, reads
  OCT- + OCT+ and the boot guard, switches the audio off for update mode and only then calls `usb_start` (it used to
  attach before the timer; `usb_poll` waits for `usb.up` as it does for `usb_retry`). MENU > SYSTEM > UPDATE MODE comes
  from a running, enumerated device: `update_only` calls `usb_uac_switch(0)`, which drops off the bus (`fm1_usb_off`,

  there. The update loader (`loader.c`) is untouched: it never had UAC, and its descriptors and image (8216 B) are the
  same as before (checked by building the old and new usb.c with the loader's defines).

# Patch format

IDs: D-250–D-299

A patch exists in two forms: the JSON the editor keeps, where **assemblies** are an **overlay** on a flat list of modules and cables, and the compact binary the FM-1 plays, whose newest format is 48 ([D-282](patch-format.md#D-282), Proposed). Module type and port indices are append-only, and a format change touches the editor, both engines, the presets and the tests in one change set. The editor migrates every old JSON patch on load and writes each patch in the lowest format that holds it, 46 or later ([D-281](patch-format.md#D-281)); the firmware reads formats 31 to 48, an older one with the parameter counts of its format, and plays the **fallback patch** for a slot it cannot load. The FM-1 keeps 64 **slots** and a **settings record** log-structured over 66 flash sectors and user presets in a separate store at 0x99000..0x9FFFF, and after an update that changes a factory patch or the format it rewrites every **untouched factory slot** with today's patch ([D-283](patch-format.md#D-283), Proposed). The FM-1 limits a patch to 64 modules, 255 cables and 3840 bytes, and browser storage keys and file formats carry the `matryoshka` name while the upstream `modular-1` names still load.

# Patch format

IDs: D-250–D-299

A patch exists in two forms: the JSON the editor keeps, where **assemblies** are an **overlay** on a flat list of modules and cables, and the compact binary the FM-1 plays, now format 36 ([D-268](patch-format.md#D-268), Proposed). Module type and port indices are append-only, and a format change touches the editor, both engines, the presets and the tests in one change set. The editor migrates every old JSON patch on load and always writes the current format; the firmware reads formats 31 to 36, an older one with the parameter counts of its format, and plays the **fallback patch** for a slot it cannot load. The FM-1 keeps 64 **slots** and a **settings record** log-structured over 66 flash sectors and user presets in a separate store at 0x99000..0x9FFFF, and after an update that changes the format it rewrites every **untouched factory slot** in the new format. The FM-1 limits a patch to 64 modules, 255 cables and 3840 bytes, and browser storage keys and file formats carry the `matryoshka` name while the upstream `modular-1` names still load.

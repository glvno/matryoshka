# Firmware install

IDs: D-150–D-199

Matryoshka installs over USB MIDI with Felucca's update protocol, from the editor's **Install panel** or `tools/fm1_install.py`, and never installs a firmware that lacks Felucca's update handling; a cut-off install is finished by running it again in the waiting **update loader**, which is fed only packages it may write. Matryoshka's firmware reports the **identity** `FM-1_7MMmmpp`, its version in two digits each (loader `ota-FM-1_700`), and the app reads other firmwares' identities to decide what to say: anything other than stock V15 or Matryoshka gets a "**return to stock** first" note, and over Felucca the install waits for a ticked warning because Matryoshka's stores overwrite Felucca's data. The published Install panel installs after one risk check box, lists what was tested on a real FM-1, asks before the tab is left during an install, and returns the FM-1 to stock with the bundled, unmodified M-VAVE V15. Setting up takes two steps: the firmware, which carries the **firmware tier** of factory patches, then the **factory region** with the other factory patches, the factory engine presets and the drum patterns, installed after the firmware unless the user opts out ([D-179](#D-179)). On the FM-1, **safe mode** plays the fallback patch compiled into the firmware, **update mode** offers only USB and updates and drops all incoming MIDI, and the firmware answers the host before it loads any patch. No firmware runs on an FM-1 before `emu:smoke` has passed on those exact bytes (the test rig may take the shorter boot check while the owner iterates), installs on the owner's FM-1 happen only in device sessions he runs, and the dev server installs this checkout's CI build.

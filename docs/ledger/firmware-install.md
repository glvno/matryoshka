# Firmware install

IDs: D-150–D-199

Matryoshka installs over USB MIDI with Felucca's update protocol, from the editor's **Install panel** or `tools/fm1_install.py`, and never installs a firmware that lacks Felucca's update handling; a cut-off install is finished by running it again in the waiting **update loader**, which is fed only packages it may write. Matryoshka's firmware reports the **identity** `FM-1_7XY` (loader `ota-FM-1_700`), and the app reads other firmwares' identities to decide what to say: anything other than stock V15 or Matryoshka gets a "**return to stock** first" note, and over Felucca the install waits for a ticked warning because Matryoshka's stores overwrite Felucca's data. The published Install panel installs after one risk check box, lists what was tested on a real FM-1, asks before the tab is left during an install, and returns the FM-1 to stock with the bundled, unmodified M-VAVE V15. On the FM-1, **safe mode** plays the fallback patch compiled into the firmware, **update mode** offers only USB and updates and drops all incoming MIDI, and the firmware answers the host before it loads any patch. No firmware runs on an FM-1 before `emu:smoke` has passed on those exact bytes, installs on the owner's FM-1 happen only in device sessions he runs, and the dev server installs this checkout's CI build.

## Not yet settled

- Whether the app can return to stock an FM-1 whose flash head (its boot code) is not V15's, such as one that ran M-VAVE Official Open — issue #183. Today the running firmware refuses such a return before it erases anything, and the screen says "update failed -5". The Install panel and `tools/fm1_install.py` then explain it and point to the chip's boot mode.
